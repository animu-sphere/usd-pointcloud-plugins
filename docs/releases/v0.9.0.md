# OpenUSD Point Cloud Plugins v0.9.0

Release date: 2026-08-15

## Summary

This feature release closes the TilePlan convergence and interactive
validation milestone. Sequential point-budget planning and COPC native
hierarchy planning now share one tile-plan representation downstream, and the
release records a reproducible host-responsiveness baseline for generated
payload-backed output.

## Breaking changes

None. Existing LAS, LAZ, COPC, and PLY format ids, file-format arguments,
authored stage shape, and fixed-grid tiling behavior remain compatible with
v0.8.0.

## Included

- A versioned `TilePlan` contract covering tile identity, bounds, point counts,
  parent and child relationships, source ranges, depth, and planner identity
  and version.
- Adaptive point-budget planner output adapted to `TilePlan` without changing
  its partitioning behavior, with the shared tile router consuming the plan.
- COPC native hierarchy nodes and byte ranges mapped to `TilePlan` instead of
  being re-derived through sequential planning.
- Planner-agnostic cache identity through the deterministic
  `TilePlanCacheArguments` and `StableTilePlanKey` contracts.
- Equivalent authored-output coverage for sequential and COPC-native plans
  describing the same partition.
- A reproducible Windows `usdview` host-responsiveness workload using the
  USGS 3DEP 4,096-point payload-backed fixture.

## Interactive verification

The workload sent `Home`, `Left`, `Right`, `Up`, and `Down` at 500 ms
intervals while sampling the complete OST process tree every 50 ms. It
synchronously dispatched `WM_NULL` with a bounded timeout for each action and
validated key-down and key-up message queuing.

| Fixture | Actions | Max UI dispatch | Stage open | Peak tree working set | Peak process working set | Samples |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| USGS 3DEP 4,096-point payload fixture | 5 | 0.132723 s | 0.027894 s | 316,616,704 B | 296,374,272 B | 48 |

The harness completed successfully and usdview exited normally. The baseline
measures bounded UI-thread dispatch latency and working-set pressure. It does
not measure renderer frame latency or a host-specific input-to-present time.
The reproduction command is documented in
[infrastructure-maturity.md](../roadmap/infrastructure-maturity.md).

## Requirements

- CMake 3.23 or newer.
- A C++17 compiler.
- OpenUSD 26.08 for USD authoring, resolver, and plugin targets.
- OpenStrata 0.21.0 for the pinned workspace build.

## Known limitations

- Resolver-backed generated-cache reuse still requires a stable validation
  token, and remote range-cache ownership remains out of scope.
- Target payload-byte and spatial-size fallback policies are not part of this
  release.
- COPC writing and new public USD schemas remain deferred.
- The host-responsiveness baseline is not a renderer frame-time or
  input-to-present measurement.
