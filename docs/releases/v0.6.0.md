# OpenUSD Point Cloud Plugins v0.6.0

Release date: 2026-08-12

## Summary

This feature release hardens deterministic generated-USDC cache reuse with a
transport-independent source identity contract, explicit lookup states,
stable diagnostics and statistics, and recovery for corrupt or interrupted
cache publication. It also records local and resolver-backed reuse baselines.

## Breaking changes

None. Existing LAS, LAZ, COPC, and PLY format ids, file-format arguments,
authored stage shape, and plugin behavior remain compatible with v0.5.0.

## Included

- `usdgeo::cache::SourceIdentity` and descriptor-derived cache compatibility
  and invalidation behavior.
- Machine-readable lookup states for missing, incomplete, hit, and invalid
  cache layouts while preserving the existing `IsCacheHit` API.
- Stable lookup statistics and diagnostics for hits, misses, incomplete
  entries, and invalid layouts.
- Validation of committed cache roots and payload references before reuse.
- Recovery that invalidates corrupt entries and interrupted publications through
  the descriptor-derived cache entry path.
- A local conversion baseline that records one miss followed by one hit for the
  same descriptor.
- A resolver-backed COPC baseline that keeps generated-cache reuse disabled
  when a stable validation token is unavailable.

## Requirements

- CMake 3.23 or newer.
- A C++17 compiler.
- OpenUSD 26.08 for USD authoring, resolver, and plugin targets.
- OpenStrata 0.21.0 for the pinned workspace build.

## Compatibility

The LAS, LAZ, COPC, and PLY plugin bundles target OpenUSD `>=26.08,<27.0` and
the `cy2026` / `usd` OpenStrata platform and profile. Generated-USDC caching
remains separate from resolver or transport byte-range caching. Resolver-backed
reuse requires stable source identity metadata and is conservatively disabled
when that metadata is unavailable.

## Known limitations

- Range-cache ownership is separate from the generated-USDC cache and is not
  provided by this repository.
- Remote generated-cache reuse is not enabled without a stable resolver
  validation token.
- Adaptive tiling, COPC writing, and new public USD schemas remain deferred.

## Verification

The release workflow validates the tag against `VERSION`, checks all release
metadata declarations, validates the OpenStrata CI matrix, runs the declared
cross-platform source and plugin lanes, packages the plugin products, and
publishes SHA-256 checksums. The v0.6.0 preparation was validated against the
local cache integration, lookup status, statistics, recovery, and resolver
cache-reuse baseline tests before tagging.
