# OpenUSD Geospatial Geometry Plugins v0.2.0

Release date: 2026-08-05

## Summary

This release expands the LAS and LAZ import surface with LAS 1.4 attributes,
waveform metadata, GeoTIFF CRS keys, Extra Bytes, metadata-only reads, and
normalized file-format arguments. It also connects bounded pull-stream reads
to spill-backed, payload-backed spatial tiling and establishes OpenUSD 26.08
`usdLod` authoring through the shared libraries.

## Breaking changes

The `usd-geo-usd` library and `geo-las` / `geo-laz` bundles were renamed to
`usd-pointcloud-authoring` and `geospatial-las` / `geospatial-laz`. This also
changes installed library names, CMake targets, bundle paths, and plugin type
names. The `las` and `laz` format ids, file extensions, diagnostic code
prefixes, file-format arguments, and authored stage remain unchanged. See the
[migration guide](../compatibility/MIGRATION.md) for the complete checklist.

## Included

- LAS 1.4 point attributes and point formats 4, 5, 9, and 10, including
  waveform packet metadata and external `.wdp` references.
- GeoTIFF CRS VLR parsing and scalar/vector Extra Bytes types 1-30, with
  descriptor scale and offset application and deterministic USD-safe names.
- Metadata-only LAS and LAZ reads, chunked and range-based reader contracts,
  normalized file-format arguments, and typed diagnostics.
- OpenUSD 26.08 `usdLod` authoring with compact `off`, `preview`, `balanced`,
  and `quality` profiles.
- Spatial tiled and payload-backed authoring through both the shared authoring
  API and the LAS/LAZ FileFormat read path.
- Bounded-memory pull-stream delivery, per-tile spill files, portable payload
  references, and cleanup/rollback coverage for tiled authoring failures.
- Module README and workspace contracts, build/install documentation, the
  compatibility migration guide, and cross-platform release CI gates.

## Requirements

- CMake 3.23 or newer.
- A C++17 compiler.
- OpenUSD 26.08 for the USD authoring and plugin targets.
- OpenStrata 0.21.0 for the pinned workspace build.

## Known limitations

- Rendering is supplied by the consuming OpenUSD application.
- Peak RSS and payload working-set measurements for real-world tiled datasets
  are not yet published; the generated-corpus stream benchmark measured
  1,000,000 points across 245 tiles with a 25.5 MiB RSS delta and 55.3 MiB
  peak spool usage on Windows/OpenUSD 26.08.
- Bounds and classification filters are not available and are rejected with
  typed diagnostics.
- GeoTIFF keys are parsed and retained but are not interpreted, and EPSG codes
  are not inferred when the WKT CRS VLR is absent.
