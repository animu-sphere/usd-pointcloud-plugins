# OpenUSD Point Cloud Plugins v0.4.0

Release date: 2026-08-12

## Summary

This feature release adds PLY 1.0 point-cloud reads through the shared point
stream and authoring contracts. It covers scalar vertex data, bounded source
streaming, explicit CRS arguments, deterministic cache lookup,
payload-backed fixed-grid tiled authoring, and adaptive display attributes.

## Breaking changes

None. Existing LAS, LAZ, and local COPC format ids, extensions, arguments,
authored stage shape, and diagnostic prefixes remain compatible with v0.3.0.
PLY is a new `ply` format id and requires an explicit `epsg` file-format
argument because PLY has no embedded CRS contract.

## Included

- ASCII, binary little-endian, and binary big-endian scalar PLY vertex decoding.
- Shared `PointStream` support for positions, RGB, intensity, classification,
  and generic scalar vertex attributes.
- Bounded source reads with chunk limits, memory budgets, point ranges, bounds,
  classification filters, and cancellation.
- The `pointcloud-ply` OpenUSD FileFormat Plugin with shared `UsdGeomPoints`
  authoring and cache lookup through `USDGEO_CACHE_ROOT`.
- Adaptive point widths and `displayColor` authoring when RGB data is available,
  including explicit 8-bit PLY and 16-bit LAS color normalization.
- Payload-backed fixed-grid PLY tiled reads using `tileSize`,
  `tileMemoryLimit`, and `payloadDirectory`.
- Stanford Bunny corpus coverage and tiled plugin integration coverage.

## Fixed

- Tiled payload identifiers and LOD extent validation remain consistent across
  COPC and PLY authoring.
- Missing LAS sources retain the source-open diagnostic classification.

## Requirements

- CMake 3.23 or newer.
- A C++17 compiler.
- OpenUSD 26.08 for USD authoring and plugin targets.
- OpenStrata 0.21.0 for the pinned workspace build.

## Known limitations

- PLY faces, arbitrary non-vertex mesh authoring, and PLY writing are out of
  scope.
- PLY metadata-only reads are not available because PLY has no reliable bounds
  or CRS metadata contract.
- Tiled planning uses the shared fixed-grid interface; adaptive depth and
  point-budget planning remain future work. Adaptive point display attributes
  are independent of tile planning.

## Verification

The release gate runs `ost configure`, `ost build`, and `ost test`, validates
release metadata, packages all plugin bundles, and publishes SHA-256 checksums.
The PLY-specific validation includes `usdPly_unit` and
`pointcloudPly_integration` with the checked-in Stanford Bunny corpus and a
payload-backed tiled conformance read.
