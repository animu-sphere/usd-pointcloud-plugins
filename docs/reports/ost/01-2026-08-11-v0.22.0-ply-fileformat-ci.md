# OST v0.22.0 readiness - PLY FileFormat CI and smoke-fixture arguments

- Date: 2026-08-11
- Release target: `v0.22.0`
- OST version exercised in CI: `ost 0.21.0`
- Runtime: `cy2026` / OpenUSD 26.08
- Platforms: Windows x86_64, macOS arm64, Linux x86_64
- Scope: `pointcloud-ply` OpenUSD FileFormat Plugin
- Pull request: [#84](https://github.com/animu-sphere/usd-pointcloud-plugins/pull/84)
- Upstream ask carried into: `ost 0.22.0`

This is the v0.22.0 readiness report for the repository. The recorded CI run
used the pinned `ost 0.21.0` toolchain available in the workspace; the report
does not claim validation against an unreleased or otherwise unobserved OST
0.22.0 binary.

## TL;DR

Adding PLY to the generated OpenStrata CI matrix exposed two repository-side
integration gaps before the lane went green:

1. The standalone PLY CMake project did not register the `usdGeoCache` and
   `usdPointCloudTiling` targets required transitively by
   `usdPointCloudAuthoring`.
2. The OpenStrata verification pyramid opens the declared smoke fixture with
   `usdcat` and `Usd.Stage.Open()` without file-format arguments. PLY has no
   embedded CRS and correctly requires an explicit `epsg` argument, so a raw
   `.ply` smoke fixture failed with `[PLY003]`.

The first issue was fixed by completing the PLY bundle's dependency registration.
The second was fixed without weakening the CRS contract: the smoke fixture is
now a small USD wrapper that references the PLY source with
`SDF_FORMAT_ARGS:epsg=4978`.

The final run passed all three PLY CI cells. The only OpenStrata follow-up for
v0.22.0 is a non-blocking usability ask: allow a smoke fixture to declare
format arguments without requiring a wrapper layer.

## 2. First failure: standalone dependency registration

The first PLY CI run failed in the standalone bundle configure step. The
relevant CMake diagnostic was the same on Windows, macOS arm64, and Linux:

```text
Target "usdPointCloudAuthoring" links to:
  usdgeo::cache
but the target was not found
```

After registering `usdgeo::cache`, the next configure pass exposed the second
missing target:

```text
Target "usdPointCloudAuthoring" links to:
  usdpointcloud::tiling
but the target was not found
```

The PLY bundle had registered `usdGeoCore`, `usdPointCloudCore`, authoring, and
`usdPly`, but not the complete dependency closure expected by the authoring
library. The fix added the same `add_subdirectory` registrations already used
by the LAS and LAZ bundles:

```cmake
if(NOT TARGET usdgeo::cache)
    add_subdirectory("${CMAKE_CURRENT_SOURCE_DIR}/../../libs/usd-geo-cache"
                     "${CMAKE_CURRENT_BINARY_DIR}/usd-geo-cache")
endif()
if(NOT TARGET usdpointcloud::tiling)
    add_subdirectory("${CMAKE_CURRENT_SOURCE_DIR}/../../libs/usd-pointcloud-tiling"
                     "${CMAKE_CURRENT_BINARY_DIR}/usd-pointcloud-tiling")
endif()
```

The corrected standalone configure and plugin build succeeded locally before
the next CI run.

## 3. Second failure: smoke fixtures cannot carry format arguments

The second run completed the PLY build on all three platforms. The verification
pyramid passed bundle inspection, library discovery, and `.ply` file-format
discovery, then failed at the two levels that open the smoke fixture:

```text
usdcat could not read the fixture:
[PLY003] PLY requires an explicit epsg file-format argument

Usd.Stage.Open() failed: Failed to open layer .../conformance.ply
```

This is the expected PLY behavior. PLY has no standard embedded CRS in the
scope implemented here, and the plugin must not guess one. The direct FileFormat
integration test already supplied the required argument:

```cpp
{{"epsg", "4978"}}
```

OpenStrata's current plugin manifest model declares smoke fixtures as a list of
relative path strings. The verification levels pass that path directly to
`usdcat` and to `Usd.Stage.Open()`. There is no fixture-level argument map in
`openstrata.plugin.yaml`, so the direct `.ply` fixture could not express the
required CRS to the generic verification runner.

## 4. The wrapper that keeps both contracts true

The smoke declaration now points to `tests/fixtures/conformance.usda`:

```yaml
tests:
  smoke:
    - tests/fixtures/conformance.usda
```

The wrapper contains the standard OpenUSD format-argument reference:

```usda
#usda 1.0

def "PointCloud" (
    references = @./conformance.ply:SDF_FORMAT_ARGS:epsg=4978@
)
{
}
```

This keeps the PLY adapter strict when a `.ply` layer is opened directly while
letting the generic OpenStrata smoke runner exercise the same adapter through a
normal USD reference. The local command used for the final verification was:

```text
$ ost plugin test plugins/pointcloud-ply --target cy2026 --profile usd --up-to 4 --json
...
"usdcat read 'conformance.usda' and emitted USDA"
"Usd.Stage.Open() opened the fixture"
"passed": true
```

The hosted run reproduced the result on all three platforms.

## 5. What worked

- `ost ci validate` accepted the expanded 24-cell matrix.
- `ost plugin build` built the PLY bundle on Windows, macOS arm64, and Linux.
- L2 discovery resolved `.ply` to the registered FileFormat on all three hosts.
- L3 `usdcat.read` and L4 `python.stage_open` passed through the USD wrapper.
- Existing LAS, LAZ, and COPC cells remained green while PLY was added.
- No OpenStrata runtime or hosted-runner defect was required to explain either
  failure; both failures were useful repository integration findings.

## Ask summary

| Priority | Ask for OpenStrata | Why it matters | Workaround used here |
| --- | --- | --- | --- |
| P2 | Let a smoke fixture declare a relative path plus format arguments, for example a structured `path` and `file_format_arguments` entry | FileFormat plugins often need arguments that cannot be embedded in the source format; generic L3/L4 verification should be able to exercise those plugins directly | A checked-in `.usda` wrapper with `SDF_FORMAT_ARGS` |

A compatible future shape could preserve the current string form and add an
optional structured form, rather than changing existing manifests. The runner
would need to apply the arguments consistently to `usdcat`, Python stage open,
and any future flatten or view level.
