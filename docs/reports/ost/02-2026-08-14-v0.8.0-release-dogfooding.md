# OST v0.8.0 release dogfooding

- Date: 2026-08-14
- Release target: `v0.8.0`
- OST version exercised locally: `ost 0.21.0`
- Runtime: `cy2026` / OpenUSD 26.08
- Platform: Windows x86_64
- Target: `cy2026-windows-x86_64-py313-usd`
- Source revision: `78a64f9` (`main`, merge of PR #118)
- Scope: release metadata, OpenStrata CI validation, full local build and test,
  and workspace plugin packaging

This report records the OpenStrata commands exercised while preparing the
v0.8.0 release. It is an engineering dogfooding record, not a release sign-off:
the source build and tests passed, but workspace packaging remains blocked by a
managed-output digest mismatch in the local OpenStrata 0.21.0 workflow.

The test set included the core libraries, LAS, LAZ, COPC, PLY, authoring,

## 4. Packaging finding

The first workspace package attempt failed closed with:

```text
error[PLUGIN_PACKAGE_OUTPUT_MISMATCH]: plugin 'httpresolver' staged package
output does not match its last managed build: digest-mismatch
'lib/libHttpResolver.dll'
```

After rebuilding all five bundles and retrying with `--clean-stage`, the same
failure remained. The final observed values were:

```text
expected sha256:2ca878b341549ce3f03ef2244c00dc6e5d033e8d8198d3db9930eea2cba1b086
observed sha256:03e5e1e23a5a2196e1d3099580ce57fe0bc4c54266beb7f32b7b7b87dffa3b9d
last managed build sha256:7c64f5fd54057803fcdaac41cec4511010b3d5e8977fece017882d1ba09533c7
```

A partial `httpresolver` package directory was created under
`plugins/httpresolver/dist/plugins/httpresolver/0.8.0/` with an archive, `manifest.json`,
`sbom.spdx.json`, and `SHA256SUMS`. Because the workspace package stopped at the
first bundle, this is not treated as a complete product and is not release
artifacts.

The available `--allow-unmanaged-output` option was not used. It would record
an explicit unmanaged override, but it would bypass the managed-output
integrity check rather than explain or fix the mismatch. The release workflow
should remain blocked until a managed package succeeds or the provenance is
explicitly reviewed and accepted.

## 5. OpenStrata follow-up ask

The local workflow needs a deterministic explanation for the difference between
the output observed in the plugin package stage and the output recorded by the
last `ost plugin build`. Rebuilding the affected bundle and using
`--clean-stage` did not converge the hashes.

Useful diagnostics for a future OST release would be:

- report the source path and stage path used for each managed output;
- emit the managed-build completion record and observed file hash together;
- identify whether the mismatch is caused by a post-build copy, linker output,
  fallback stage, or package-stage ownership; and
- provide a supported clean rebuild/package command that guarantees the staged
  bytes are the bytes recorded by `ost plugin build`.

Until that behavior is understood, `PLUGIN_PACKAGE_OUTPUT_MISMATCH` is a valid
release blocker rather than a packaging warning.
